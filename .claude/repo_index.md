## Top-level files

- `Cargo.toml` — Root workspace manifest; lists all workspace members (~60 crates) and defines the `[workspace.metadata] initrd = [...]` list controlling which programs ship in the boot image.
- `Cargo.lock` — Locked dependency versions for the whole workspace.
- `.cargo/config.toml` — Defines the `cargo xtask`/`build-all`/`check-all`/`doc-all`/`make-image`/`start-qemu`/`toolchain` aliases (all shell out to `tools/xtask`), plus global rustflags/rustdocflags.
- `rust-toolchain` — Pins the nightly Rust toolchain channel (`nightly-2026-01-08`) and required rustup components (rustfmt, clippy, cargo, rust-src, rust-analyzer).
- `.rustfmt.toml` — Formatting rules: edition 2021, `imports_granularity = "Crate"`, `group_imports = "StdExternalCrate"`, comments wrapped at 100 cols.
- `.pre-commit-config.yaml` — Pre-commit hooks: trailing-whitespace/EOF fixers, large-file check, and a local hook running `cargo fmt --all`.
- `.gitmodules` — Registers ~20 git submodules, mostly under `src/ports/` (forked third-party crates, usually on a `twizzler` branch under the `twizzler-operating-system` GitHub org) plus `toolchain/src/*` (upstream LLVM/rustc/libc sources for bootstrapping).
- `init.sh` — First-time setup script; installs host build dependencies (QEMU, e2fsprogs/mke2fs, build-essential, etc.) for Debian/macOS.
- `flake.nix` / `flake.lock` — Nix flake providing a reproducible dev shell with the host build dependencies.
- `.envrc` — direnv hook (loads the Nix flake shell).
- `.gdbinit` — GDB startup config for kernel debugging (pairs with `cargo start-qemu --gdb <port>`).
- `README.md` — Top-level project overview/links.
- `LICENSE` — Project license.
- `.github/workflows/ci.yml` — Top-level CI orchestrator: routes push-to-main through `release.yml` then `build-and-test.yml` then `docs.yml`; routes PRs through `build-and-test.yml` only.
- `.github/workflows/build-and-test.yml` — Self-hosted CI job: inits submodules, bootstraps/pulls the toolchain, runs `cargo build-all`, then `cargo start-qemu --tests` in both debug and release. Sets `LLVM_CONFIG_PATH=llvm-config-18`, `CC=clang-18`, `CXX=clang++-18`, `LD=clang++-18`.
- `.github/workflows/release.yml` — Builds and publishes toolchain/release artifacts on push to main.
- `.github/workflows/docs.yml` — Builds and publishes rustdoc + the mdBook (`doc/`).
- `.github/actions/setup` — Composite action installing host CI dependencies.

## src/kernel

`twizzler-kernel` is a `no_std` Rust binary (`package.metadata.twizzler-build = "kernel"`, compiled for the `*-none` target triple) implementing the Twizzler object-based persistent-memory OS kernel. Key dependencies: `intrusive-collections` (nightly, used pervasively for hand-rolled wait/run queues), `twizzler-abi`/`twizzler-rt-abi` (syscall/ABI layer, built with the `kernel` feature), `twizzler-security` (capability/security-context primitives), `limine` (bootloader protocol), `acpi`/`x86`/`uart_16550`/`rdrand` (x86_64-only), `arm64`/`tock-registers`/`fdt`/`smccc`/`arm-gic` (aarch64-only), `ferroc` (global allocator, `kernel` feature), plus crypto crates (`p256`, `sha2`, `chacha20`, `digest`) for the Fortuna CSPRNG and capability signing, and `addr2line`/`object`/`backtracer_core` for panic backtraces. A small companion crate `twizzler-kernel-macros` (in `macros/`) provides the `#[kernel_test]` proc-macro attribute used by the in-kernel test harness.

### top level (src/)
- `src/kernel/src/main.rs` — kernel entry point/crate root; defines `no_std`/`no_main` setup, the `BootInfo` trait, the `Logger`, module tree, `test_runner`, `init_threading`, and `idle_main`.
- `src/kernel/src/clock.rs` — software/hardware clock abstraction: tick sources, timeout queue (`TimeoutQueue`/`TimeoutKey`/`TimeoutEntry`), oneshot-tick scheduling, and syscall support for enumerating clocks.
- `src/kernel/src/condvar.rs` — `CondVar`: a condition variable keyed by thread ObjID, backed by an intrusive `RBTree` of waiting `ThreadRef`s (`CondVarLinkAdapter`), used by mutex/tracker/pager code.
- `src/kernel/src/crypto.rs` — thin wrappers around `sha256`, ECDSA `sign`/`verify` (p256) used for capability signing/verification.
- `src/kernel/src/device.rs` — Kernel State Object (KSO) device tree management: `Device`, `DeviceInner`, bus-root/device creation, `kaction` dispatch (device driver control-plane syscall handler).
- `src/kernel/src/idcounter.rs` — generic monotonically-increasing/reusable ID allocator (`IdCounter`, `Id`, `SimpleId`, `StableId` trait) used by object/context/lock-tracker code for stable small integer IDs.
- `src/kernel/src/image.rs` — parses the kernel's own ELF image (via `xmas_elf`) to find the TLS template (`TlsInfo`) and dispatches to arch-specific TLS variant setup.
- `src/kernel/src/initrd.rs` — parses boot modules (initrd tar) into `BootObjects`/`BootModule`, creating in-kernel objects from the embedded initrd at boot.
- `src/kernel/src/instant.rs` — `Instant` monotonic timestamp type built on the registered bench clock.
- `src/kernel/src/interrupt.rs` — architecture-independent interrupt core: enable/disable, `WakeInfo`/`Interrupt`/`DeviceInterrupter` for userspace-visible interrupt delivery via wait words, `GlobalInterruptState`, `InterruptQueue`, dynamic interrupt vector allocation.
- `src/kernel/src/log.rs` — kernel console (`KernelConsole`) implementation: ring buffer, read/write syscall plumbing, `EmergencyMessage`/`NormalMessage` levels, `_print_debug`/`_print_normal`/`_print_emergency` macros' backing functions.
- `src/kernel/src/mutex.rs` — sleeping `Mutex<T>`/`LockGuard`: blocks contending threads (via scheduler integration) rather than spinning; doc comment notes priority-forwarding is currently disabled (TODO).
- `src/kernel/src/once.rs` — `Once<T>` and `OnceWait<T>`: one-time lazy initialization primitives with spin/condvar-based waiting.
- `src/kernel/src/operations.rs` — small helpers: `map_object_into_context`, `read_object`.
- `src/kernel/src/panic.rs` — panic handler support: loads DWARF debug info from the kernel ELF (via `addr2line`) and produces symbolized `backtrace()`s.
- `src/kernel/src/queue.rs` — `QueueObject<S,C>`/`ManagedQueueSender`/`ManagedQueueReceiver`/`Outstanding<C>`: kernel-side wrapper around `twizzler-queue-raw` submission/completion queues (used e.g. by the pager).
- `src/kernel/src/security.rs` — `SecurityContext`, `SecCtxMgr`, `AccessInfo`, capability lookup/caching (`PermsInfo`), security-context switch/attach syscalls, wraps `twizzler-security`.
- `src/kernel/src/spinlock.rs` — `GenericSpinlock<T, Relax>`/`LockGuard`, `RelaxStrategy` trait with `Reschedule` and `SpinLoop` policies; integrates with lock-tracking (`thread::locktrack`).
- `src/kernel/src/time.rs` — `Ticks`, `ClockHardware` trait, tick-source registry (`TICK_SOURCES`), `TimeStatCollector` (mean/variance/min/max stats).
- `src/kernel/src/userinit.rs` — constructs the initial userspace init object/environment (`create_blank_object`, name object, `KernelInitInfo`) handed off to the first user thread.
- `src/kernel/src/utils.rs` — `align`, deadlock-avoiding `lock_two`/`spinlock_two` (locks two mutexes/spinlocks in address order), `quick_random`, micro-benchmark helper `benchmark`.

### arch/ (per-ISA: amd64, aarch64)
- `src/kernel/src/arch/mod.rs` — re-exports `amd64` or `aarch64` based on `target_arch`.

- `src/kernel/src/arch/amd64/acpi.rs` — `AcpiHandlerImpl` (ACPI crate physical-memory-mapping callback), root ACPI table accessor.

- `src/kernel/src/arch/amd64/context.rs` — `ArchContext`/`ArchContextTarget`: per-security-context x86 page-table root wrapper, map/unmap/change/readmap operations.

- `src/kernel/src/arch/amd64/image.rs` — arch-specific TLS init entry (delegates to `image::init_tls` with Variant2).
- `src/kernel/src/arch/amd64/interrupt.rs` — `IsrContext` (interrupt/exception register frame, convertible to/from `UpcallFrame`), IDT construction (`InterruptDescriptorTable`, `IDTEntry`), `Exception`, `InterProcessorInterrupt` enum, vector allocation.
- `src/kernel/src/arch/amd64/ioapic.rs` — I/O APIC parsing (from ACPI MADT) and configuration (`IOApic`, `init`).
- `src/kernel/src/arch/amd64/pit.rs` — legacy 8254 PIT driver used for calibration/timing (`setup_freq`, `wait_ns`).
- `src/kernel/src/arch/amd64/processor.rs` — `ArchProcessor` (per-CPU arch state), CPU enumeration/topology, `MwaitInfo`, `halt_and_wait`, GS-relative scratch state.
- `src/kernel/src/arch/amd64/start.rs` — Limine boot-info glue (`LimineBootInfo`, `BootInfoSystemTable`, memory-map translation).
- `src/kernel/src/arch/amd64/syscall.rs` — `X86SyscallContext` implementing `SyscallContext`/`UpcallAble`, converts to `UpcallFrame`.
- `src/kernel/src/arch/amd64/thread.rs` — `ArchThread`, `Registers`, `UpcallAble` trait, thread register save/restore, upcall frame queuing, XSAVE-based extended state handling.
- `src/kernel/src/arch/amd64/tsc.rs` — `Tsc` `ClockHardware` implementation using the x86 timestamp counter, calibrated against PIT.
- `src/kernel/src/arch/amd64/apic/mod.rs` — re-exports the APIC submodules.
- `src/kernel/src/arch/amd64/apic/ipi.rs` — raw IPI send routines (`raw_send_ipi`, `send_ipi`) targeting the local APIC ICR.
- `src/kernel/src/arch/amd64/apic/local.rs` — `Lapic` register wrapper: EOI, ICR writes, oneshot timer setup, global lazy accessor (`get_lapic`).
- `src/kernel/src/arch/amd64/apic/trampolines.rs` — real-mode AP trampoline setup/`poke_cpu` for SMP bring-up (INIT/SIPI sequence).
- `src/kernel/src/arch/amd64/memory.rs` — `phys_to_virt` (identity-mapped higher-half offset) plus `frame`/`pagetables` submodules.
- `src/kernel/src/arch/amd64/memory/frame.rs` — defines `FRAME_SIZE = 0x1000`.
- `src/kernel/src/arch/amd64/memory/pagetables.rs` — re-exports `consistency`/`entry`/`table` submodules for the x86 page-table implementation.
- `src/kernel/src/arch/amd64/memory/pagetables/consistency.rs` — `TlbInvData`, `ArchCacheLineMgr`, `ArchTlbMgr` (arch TLB shootdown/invalidation state), `InvInstruction`, IPI-driven TLB shootdown handler.
- `src/kernel/src/arch/amd64/memory/pagetables/entry.rs` — `Entry`/`EntryFlags` (x86-64 page-table entry bit layout, incl. object-table marker bit) and conversion to generic `MappingSettings`.
- `src/kernel/src/arch/amd64/memory/pagetables/table.rs` — `Table` (fixed 512-entry page table), `Index`/`IndexMut`, level math (`level_to_page_size`, `next_level`).

#### arch/aarch64

- `src/kernel/src/arch/aarch64/address.rs` — `VirtAddr`/`PhysAddr` newtypes for ARMv8-A (queries `ID_AA64MMFR0_EL1` for valid PA range).

- `src/kernel/src/arch/aarch64/interrupt.rs` — DAIF-based interrupt enable/disable, IPI send, dynamic vector allocation, dispatch to `cntp`/`exception` handlers.

- `src/kernel/src/arch/aarch64/start.rs` — Limine-based boot info (`Armv8BootInfo`, `BootInfoSystemTable`) parsing for aarch64.
- `src/kernel/src/arch/aarch64/syscall.rs` — `Armv8SyscallContext` implementing `SyscallContext`, ARM PCS-based syscall register convention, `handle_syscall`.

- `src/kernel/src/arch/aarch64/memory/pagetables/consistency.rs` — `ArchCacheLineMgr`, `TlbInvData`/`TlbInvQueue`, `ArchTlbMgr` for ARM TLB/cache maintenance.
- `src/kernel/src/arch/aarch64/memory/pagetables/entry.rs` — `Entry`/`EntryFlags` (ARMv8 translation table descriptor bit layout), conversion to `MappingSettings`.
- `src/kernel/src/arch/aarch64/memory/pagetables/mair.rs` — `MemoryAttributeManager`/`MemoryAttribute` wrapping the MAIR_EL1 register (memory-type/cacheability attribute indices).
- `src/kernel/src/arch/aarch64/memory/pagetables/table.rs` — `Table` (ARM page table, entry indexing/level math), analogous to the amd64 version.

### memory/ (generic memory management: physical frames, page tables, virtual memory contexts, allocator)
- `src/kernel/src/memory/mod.rs` — top-level memory init (`init`, `prep_smp`), `MemoryRegion`/`MemoryRegionKind`, memory-pressure simulation, stats aggregation.
- `src/kernel/src/memory/allocator.rs` — `KernelAllocator` (global allocator, implements `GlobalAlloc`) plus `EarlyAllocator` bootstrap bump allocator used before the tracker is ready.
- `src/kernel/src/memory/frame.rs` — physical frame allocator: `Frame` (per-frame metadata incl. refcount/COW/zeroed/wired flags), `PhysicalFrameAllocator`, `FrameIndexer`, `AllocationRegion`/`AllocationRegionLevel` (buddy-like region tracking), frame split/merge.
- `src/kernel/src/memory/tracker.rs` — `MemoryTracker`/`FrameAllocator` (per-operation frame reservation/precharging), `ReclaimThread` (background reclaim under memory pressure), pager page accounting.
- `src/kernel/src/memory/context.rs` — `UserContext`/`KernelMemoryContext`/`KernelObjectHandle` traits (the seams generic kernel code uses to manipulate memory contexts) and `ObjectContextInfo`; re-exports `virtmem`.
- `src/kernel/src/memory/context/virtmem.rs` — `VirtContext` (the concrete `UserContext`/`KernelMemoryContext` impl): per-security-context slot table, `Slot`, `ObjectPageProvider`, `GlobalPageAlloc`, `KernelObjectVirtHandle`, `PageFaultFlags`.
- `src/kernel/src/memory/context/virtmem/fault.rs` — `do_page_fault`/`page_fault`: page-fault entry point, `FaultStats`, dispatches to object-backed COW/zero-fill/pager logic.
- `src/kernel/src/memory/context/virtmem/region.rs` — `MapRegion` (one object mapping within a context) and `RegionManager` (interval-tree of mapped regions), invalidate/ctrl operations.
- `src/kernel/src/memory/context/virtmem/tests.rs` — `#[kernel_test]`s for kernel-object mapping via `VirtContext`.
- `src/kernel/src/memory/pagetables.rs` — module aggregator re-exporting `Consistency`, `MappingCursor`, `Mapper`, `PhysAddrProvider`/`ContiguousProvider`/`ZeroPageProvider`, `MapReader`, `MappingFlags`/`MappingSettings`, `Table`.
- `src/kernel/src/memory/pagetables/consistency.rs` — arch-independent `Consistency` (batches TLB/cache invalidation work) and `DeferredUnmappingOps` (deferred frame frees run after invalidation completes).
- `src/kernel/src/memory/pagetables/cursor.rs` — `MappingCursor`: address-range cursor used to drive page-table walks (`advance`, `align_advance`, `biggest_level`).
- `src/kernel/src/memory/pagetables/mapper.rs` — `Mapper`: the generic page-table manipulation API (map/unmap/change/object_map/setup_cow_range/setup_zero_range), arch-independent, built atop arch `Entry`/`Table`.
- `src/kernel/src/memory/pagetables/phys_provider.rs` — `PhysAddrProvider` trait plus `ZeroPageProvider` (allocates zeroed frames on demand) and `ContiguousProvider` (walks a fixed physical range) implementations.
- `src/kernel/src/memory/pagetables/reader.rs` — `MapReader`/`MapCoalescer`/`MapInfo`: iterates existing mappings for a cursor, coalescing adjacent entries.
- `src/kernel/src/memory/pagetables/settings.rs` — `MappingFlags` (GLOBAL/USER/WIRED) and `MappingSettings` (perms+cache+flags triple).
- `src/kernel/src/memory/pagetables/table.rs` — generic `Table` extension methods: `setup_cow_range`, `with_dirty_bits`, table-walk helpers layered on the arch `Entry`/`Table`.
- `src/kernel/src/memory/pagetables/tests.rs` — `#[kernel_test]`s exercising the `Mapper`/page-table stack directly.

### obj/ (in-kernel object system)
- `src/kernel/src/obj/mod.rs` — `Object` (the core in-kernel object struct) and `PageNumber`; object lifecycle (`new`, `new_kernel[_with_id]`, `mark_for_delete`), `InvalidateMode`, page-table lock accessor.
- `src/kernel/src/obj/control.rs` — `ControlObjectCacher<Base>` (caches a small "base" struct for control objects without a full kernel-object mapping when it fits in one page) and `VNotes` (per-object key/value notes used by e.g. debug/annotation syscalls).
- `src/kernel/src/obj/data.rs` — bulk data operations on `Object`: `read_at`/`write_at`/`read_bytes`/`write_bytes`, atomic 32/64-bit ops, `pin`, `ensure_in_core`/`ensure_in_core_pager` (bring pages in via pager), `direct_copy`/`cow_copy`/`copy_range`, `zero_range`, `obj_memcmp`.
- `src/kernel/src/obj/id.rs` — object ID calculation/verification: `calculate_new_id`, `check_id` (validates an object's content-derived ID via nonce/kuid).
- `src/kernel/src/obj/pagetables.rs` — `ObjectPageTable`/`DirtyList`/`FindFrameFlags`: per-object page table wrapping the generic `Mapper`, including COW setup, dirty-page tracking, invalidation batching (`MAX_INVL_TARGETS`/`MAX_INVLS`).
- `src/kernel/src/obj/tests.rs` — `#[kernel_test]`s for object slice copy correctness.
- `src/kernel/src/obj/thread_sync.rs` — `SleepInfo`/`ThreadSleepLinker`/`ThreadSleepAdapter`/`SleepEntry`: per-object wait-word sleep queues (an intrusive `RBTree` keyed by offset) backing `sys_thread_sync`'s object-relative sleep/wake; also wires device-interrupt wakeups into the same mechanism.
- `src/kernel/src/obj/ties.rs` — `TiesStatic`/`Ties<K,V>`: tracks dependency ("tie") relationships between objects so deletion of a tied-to object can be deferred/tracked (`delete_object`, `lookup_deleted`).

### processor/ (scheduler, run queues, per-CPU state, IPIs)
- `src/kernel/src/processor.rs` — `Processor` (per-CPU state: stats, idle thread, current priority/load, rebalance flag), `spin_wait_until` helper.
- `src/kernel/src/processor/mp.rs` — SMP bring-up: `init_cpu`, `secondary_entry`, `boot_all_secondaries`, `register`, global `Processor` table (`current_processor`, `get_processor`, `all_processors`, `with_each_active_processor`).
- `src/kernel/src/processor/ipi.rs` — `IpiTask`: closure-based cross-CPU work dispatch (`ipi_exec`) and its generic IPI vector handler.
- `src/kernel/src/processor/rq.rs` — `RunQueue<N>` (per-CPU run queue, `NR_QUEUES = 8`), `SchedSpinlock`/`SchedLockGuard` (a spinlock specialized for scheduler-internal state that tracks critical-section entry on the current thread), `insert`/`take`/`timeslice`/`deadline` logic.
- `src/kernel/src/processor/sched.rs` — the scheduler core (module doc explains it is modeled on FreeBSD's ULE scheduler): `CPUTopoNode`/`CPUTopoType`/`CpuSet` (CPU topology), `SchedFlags` bitflags, `schedule`/`schedule_new_thread`/`schedule_thread`/`schedule_hardtick`/`schedule_stattick`/`schedule_maybe_rebalance`/`schedule_maybe_preempt`, idle-thread creation, thread enumeration (`with_all_threads`, `lookup_thread_repr`).
- `src/kernel/src/processor/timeshare.rs` — `TimeshareQueue<N>`: the calendar-queue implementation backing the User-priority run queue (insert/take/advance markers), described in `sched.rs`'s module doc.

### thread/ (thread lifecycle, suspend, per-thread timing)
- `src/kernel/src/thread.rs` — `Thread`/`ThreadRef` core struct: state (`ExecutionState`), critical-section tracking (`CriticalGuard`, `do_critical`/`enter_critical`), upcall delivery (`send_upcall`), exit path (`exit`, `force_exit`, `maybe_exit`), trace-sampling hooks, `current_thread_ref`/`current_memory_context` thread-local accessors.
- `src/kernel/src/thread/entry.rs` — new-thread bootstrap: `start_new_user`/`start_new_init`/`start_new_kernel`, `run_closure_in_new_thread`/`KthreadClosure` (kernel-thread-with-return-value helper).
- `src/kernel/src/thread/flags.rs` — bitflag constants on `Thread.flags` (`THREAD_PROC_IDLE`, `THREAD_IN_KERNEL`, `THREAD_IS_SYNC_SLEEP[_DONE]`, `THREAD_IS_EXITING`, `THREAD_IS_SUSPENDED`, `THREAD_MUST_SUSPEND`, `THREAD_MUST_EXIT`, `THREAD_MUTEX_WAIT`) plus `enter_kernel`/`exit_kernel` transition hooks.
- `src/kernel/src/thread/locktrack.rs` — `LockTracker`/`LockTrackerInner`/`Lock`: per-thread record of currently-held/intended-to-lock mutexes and spinlocks (bounded `heapless::Vec`s), used for deadlock/lock-stats diagnostics (`print_locks`, `check_timed_out_mutexes`).
- `src/kernel/src/thread/priority.rs` — `PriorityClass` (Idle/Background/User/Realtime), `Priority`, `ThreadPriority` (current + donated), priority donation (`donate_priority`, `get_donated_priority`).
- `src/kernel/src/thread/suspend.rs` — thread suspend/resume: global `SUSPENDED_THREADS` intrusive `RBTree`, `suspend`/`maybe_suspend_self`/`unsuspend_thread`, cross-CPU suspend via IPI.
- `src/kernel/src/thread/time.rs` — `ThreadStats` (user/sys/idle time), `ThreadSched` (scheduler-facing per-thread fields: pinned CPU, deadline, timeslice, current run-queue).

### syscall/ (syscall entry points)
- `src/kernel/src/syscall/mod.rs` — `SyscallContext` trait (arch-specific register access abstraction) and `syscall_entry`: the central dispatch `match` over `Syscall` variants, tracing entry/exit events.
- `src/kernel/src/syscall/object.rs` — object-related syscalls: `sys_object_create`, `sys_object_map`/`sys_object_unmap`/`sys_object_readmap`, `sys_object_info`, `ObjectHandle` trait, handle management (`sys_new_handle`/`sys_unbind_handle`, `count_handles`), `object_ctrl`/`map_ctrl` (sync/delete/preload/notes), `sys_enumerate`, `sys_sctx_attach`.
- `src/kernel/src/syscall/stat.rs` — `write_sys_info_values`: fills in `SysInfo`/`MemoryStats`/`ThreadStats`/`SctxStats`/`LockStats`/`SyscallStats`/`ObjectStats` for the `SysInfo`/stat syscall.
- `src/kernel/src/syscall/sync.rs` — `sys_thread_sync` and its support: `Requeue` (deferred wake list), `prep_sleep`/`wakeup`/`optimized_single_sleep`/`optimized_single_wake`, `finish_blocking`, trace hooks (`trace_block`/`trace_resume`).
- `src/kernel/src/syscall/thread.rs` — `sys_spawn`, `thread_ctrl` dispatch over `ThreadControl` (GetUpcall/SetUpcall/ResumeFromUpcall/SetTls/GetTls/Exit/Yield/GetSelfId/sctx switch/GetStats/ReadRegisters/ChangeState/trace-events/SendMessage).

### pager/ (in-kernel pager-request machinery — talks to the userspace pager server)

- `src/kernel/src/pager/queues.rs` — kernel-to-pager and pager-to-kernel queue management: `submit_pager_request`, `init_pager_queue`, translates `RequestFromKernel`/`CompletionToKernel`/`RequestFromPager`/`CompletionToPager` wire types.
- `src/kernel/src/pager/request.rs` — `ReqKind` (info/page-data/sync/sync-region/delete/create/pager-memory request variants) and `Request` (per-inflight-request state: completion tracking, timeout, `SyncRegionInfo`).

### trace/ (kernel tracing subsystem)

### random/ (entropy sources and CSPRNG)

- `src/kernel/src/random/cpu_trng/mod.rs` — `CpuEntropy`: `EntropySource` wrapping the CPU's hardware RNG instruction (RDSEED on x86_64, RNDR on aarch64 via `rndrs`).
- `src/kernel/src/random/cpu_trng/rndrs.rs` — `Rndrs`: ARM `RNDR`/`RNDRRS` instruction wrapper (noted as untested — no available hardware).
- `src/kernel/src/random/fortuna/mod.rs` — `Contributor`/`Accumulator`: Fortuna CSPRNG pool-accumulation logic (Ferguson/Schneier "Cryptography Engineering" ch. 9), `try_fill_random_data`.
- `src/kernel/src/random/fortuna/error.rs` — `Error` enum (Unseeded/TooMuchData/TooLittleData/PoolNumTooBig).
- `src/kernel/src/random/fortuna/internal.rs` — `Generator`: ChaCha20+SHA256-based Fortuna internal generator (256-bit key + 128-bit counter), `reseed`/`generate_random_data`.
- `src/kernel/src/random/fortuna/pool.rs` — `Pool`: one of Fortuna's SHA256-based entropy pools (`insert`/`result`/`count`).

### macros/ (companion proc-macro crate, `twizzler-kernel-macros`)
- `src/kernel/macros/src/lib.rs` — `#[kernel_test]` proc-macro attribute: rewrites a test function so its name is captured and it can be registered with the custom `#[test_case]`-based kernel test harness (worked around because Rust doesn't expose test names to custom test runners, per the file's comment).

## src/lib/dynlink

Package `dynlink` — the userspace dynamic linker used to load ELF dynamic shared objects (DSOs) into compartments, perform relocation, and manage TLS. Depends on `twizzler-abi`, `twizzler-rt-abi`, `secgate` (for `RawSecGateInfo`, used to discover gate call points during loading), `petgraph` (dependency graph), `elf` (ELF parsing), `thiserror`/`miette` (errors), `tracing`.

- `src/lib/dynlink/src/lib.rs` — crate root and extensive doc comment explaining DSO loading/relocation/TLS concepts; wires up all submodules (`compartment`, `context`, `library`, `symbol`, `tls`, `engines`, `arch`, `error`).
- `src/lib/dynlink/src/error.rs` — `DynlinkError`/`DynlinkErrorKind`/`HeaderError`: structured, `miette`-diagnosable error types for every stage of linking.
- `src/lib/dynlink/src/library.rs` — `Library`/`UnloadedLibrary`/`LibraryId`/`SecgateInfo`/`AllowedGates`: represents a single loaded (or not-yet-loaded) ELF DSO — program headers, dynamic table access, entry-point lookup, and enumeration of its secgate call points (`iter_secgates`).
- `src/lib/dynlink/src/symbol.rs` — `RelocatedSymbol<'lib>`/`LookupFlags`: a resolved symbol paired with its owning `Library`, used during relocation and dependency search.
- `src/lib/dynlink/src/tls.rs` — ELF TLS Variant I/II implementation: `TlsVariant`, `TlsModule`, `TlsModId`, `TlsRegion` — allocation and layout of per-thread storage across libraries.
- `src/lib/dynlink/src/compartment.rs` — `Compartment`/`CompartmentId`: an isolation unit containing a set of libraries plus per-compartment TLS generation tracking.

## src/rt and src/abi — userspace runtimes and the runtime ABI

## src/rt/rt (wrapper)

Package `twizzler-runtime` (`src/rt/Cargo.toml`, no deps). This is the thin wrapper crate that userspace programs link against instead of `reference` directly — its entire job is to force the linker to pull in the reference runtime's cdylib (`twz_rt`).

- `src/rt/src/lib.rs` — the whole crate: `#[link(name = "twz_rt")] extern "C-unwind" {}`, i.e. a no-op body whose only purpose is the `#[link]` attribute forcing linkage against the `twz_rt` (reference runtime) shared object.

## src/rt/reference

Package `twz-rt` (`src/rt/reference/Cargo.toml`), built as a `cdylib`. This is the default dynamic-linking Twizzler runtime ("reference runtime"): implements the full `twz_rt_*` C ABI (allocator, objects, threads, files/sockets, exec, TLS, debug info, time) on top of `twizzler-abi` syscalls, `dynlink` (dynamic linking), `monitor-api`/`secgate` (talking to the monitor), plus `smoltcp` for a userspace TCP/IP stack, `ferroc`/`talc` for allocation, and `naming-core`/`pager-dynamic`/`twizzler-io`/`twizzler-net` for filesystem-ish/network naming and I/O.

- `src/rt/reference/src/lib.rs` — crate root; declares feature gates and re-exports (`arch`, `runtime`, `error`, `preinit`, `syms`, `pager` modules); re-exports `set_upcall_handler`, `RuntimeState`, `OUR_RUNTIME`.
- `src/rt/reference/src/preinit.rs` — early-init formatted printing (`PreinitLogger` implementing `fmt::Write` over the kernel console) plus `preinit_abort`/`preinit_unwrap*` helpers used before the panic runtime is ready.
- `src/rt/reference/src/error.rs` — `RuntimeError` enum (`Unknown`, `PoisonError`) with a `From<PoisonError<T>>` impl for internal std-mutex-poison handling.
- `src/rt/reference/src/pager.rs` — one line: re-exports everything from the external `pager_dynamic` crate.
- `src/rt/reference/src/syms.rs` — the C ABI export surface: ~90+ `extern "C-unwind" twz_rt_*` functions (malloc/dealloc, fd ops, thread spawn/join, object map/create, TLS, time, sysinfo, get_random, `dl_iterate_phdr`, plus libc shims like `malloc`/`free`/`getenv`/`fwrite`/`fprintf`) that satisfy `twizzler_rt_abi::bindings`, verified against the bindgen signatures via a `check_ffi_type!` macro.

## src/srv and src/bin — system servers and userspace programs

## src/srv/cache-srv

Object caching/pinning server: keeps objects mapped ("held") in memory so their pages stay resident, tracking who's holding what for stats. Cargo package `cache-srv` (crate-type `cdylib` — compiled both as an rlib for the client trampoline and a `.so` exporting secgate entry points); deps: `twizzler-abi`, `twizzler-runtime`, `secgate`, `twizzler-rt-abi`, `tracing`.

- `src/srv/cache-srv/src/lib.rs` — `CacheState`/`HeldObject` track a `BTreeMap<(ObjID, MapFlags), HeldObject>` of mapped-and-held object handles with hold start time; secgate entries `hold`, `drop`, `preload`, `stat`, `list_nth` let clients pin/unpin objects and enumerate cache stats (`CachedStats`).

## src/srv/devmgr-srv

Device-manager server: enumerates the PCIe bus at boot and lets other compartments request matching devices by driver spec. Package `devmgr-srv` (cdylib); deps: `twizzler-driver`, `pci_types`, `devmgr`, `twizzler`, `secgate`.

- `src/srv/devmgr-srv/src/lib.rs` — scans the PCIe bus (`start_pcie`/`start_pcie_device`, using `Device::kaction` with `PcieKactionSpecific::RegisterDevice`) and registers found devices; secgate entries `devmgr_start()` (kicks off the scan) and `get_devices(spec: DriverSpec) -> ObjID` (returns an `OwnedDevice`-backed object matching a `DriverSpec`/`Supported` filter, used by other servers like pager-srv's NVMe code and net-srv).

## src/srv/display-srv

Display/window-server: owns the virtio-gpu device and framebuffer, and hands out per-client windows. Package `display-srv` (cdylib); deps: `twizzler-display`, `virtio-gpu`, `secgate`.

- `src/srv/display-srv/src/lib.rs` — `DisplayInfo` (global GPU/framebuffer state + `HandleMgr<DisplayClient>`) and `DisplayClient` (per-window `BufferObject` + `WindowConfig`); secgate entries `start_display()` (probes virtio-gpu, sets up the framebuffer), `create_window`, `drop_window`, `reconfigure_window`, `get_window_config`, `get_display_info`.

## src/srv/logboi-srv

Centralized logging server ("log booth"): buffers client log messages and writes them to the kernel console. Package `logboi-srv` (cdylib); deps: `logboi` (client lib), `secgate`.

- `src/srv/logboi-srv/src/lib.rs` — `LogClient` (per-client `SimpleBuffer`) and `Logger` (`HandleMgr<LogClient>`); secgate entries `logboi_open_handle`, `logboi_close_handle`, `logboi_post` (client writes into its `SimpleBuffer`, server relays via `sys_kernel_console_write`).

## src/srv/naming-srv

Naming/namespace server backing the Twizzler filesystem-like naming hierarchy (paths -> object IDs). Package `naming-srv` (cdylib); deps: `naming-core` (the actual `NameStore`/`NameSession` tree impl), `naming` (client lib), `pager`, `twizzler`.

## src/srv/net-srv

Networking server: owns the virtio-net device and a smoltcp stack, brokers TCP/UDP sockets and port allocation to clients. Package `net-srv` (cdylib); deps: `smoltcp`, `virtio-net`, `twizzler-net`, `twizzler-queue`, `twizzler-driver`.

- `src/srv/net-srv/src/device.rs` — `device_thread`/`device_thread_main`: background thread driving the virtio-net `DeviceWrapper<TwizzlerTransport>` poll loop (smoltcp interface polling, socket processing).
- `src/srv/net-srv/src/gates.rs` — secgate entries: `start_network()` (bring up smoltcp iface with a hardcoded QEMU user-net IP/gateway, spawn device thread), `twz_net_alloc_port`, `twz_net_release_port`, `twz_net_drop_client`, `twz_net_open_client` (the client-facing socket API, using `ClientMsg`/`ServerMsg` from `twizzler-net`).

## src/srv/pager-srv

The pager: services page-fault/page-in-out requests from the kernel over a queue, backing objects with an on-disk (NVMe) or in-memory (virtio-mem) store, including an ext4-based and a Lethe (provable-deletion, encrypted) object store. Package `pager-srv` (cdylib); deps: `object-store` (sibling crate below), `twizzler-driver`, `twizzler-queue`, `nvme` (nvme-rs), `devmgr`, `async-executor`/`async-io`/`polling`/`futures` (its own thread-pool + async runtime), `bitvec`, `heapless`.

- `src/srv/pager-srv/src/lib.rs` — `PagerContext` (global state: object store handle, physical memory tracker, notify-kernel completion queue) and startup: `pager_start(q1, q2)` secgate entry (wires up the two kernel<->pager queues, starts worker threads, NVMe/virtio-mem probing), plus `adv_lethe()` (advance the Lethe epoch, i.e. commit provable deletion) and `disk_len(id)`.

## src/bin/top

Interactive terminal process/thread monitor (like Unix `top`), showing per-thread scheduler stats. Package `top`; deps: `crossterm`, `twizzler`.

- `src/bin/top/src/main.rs` — `ThreadInfo`/`ThreadTracker`; raw-mode alternate-screen TUI polling `sys_thread_read_stats`/`ThreadRepr`/`ExecutionState` via `sys_enumerate`(`EnumerateKind`) on a 1s timer to show live thread CPU/scheduling stats.

## src/bin/trace

`trace` — CLI to enable kernel tracing (`TraceSpec`) for a target program/event set and report aggregated stats, similar to `strace`/`perf stat`. Package `trace`; deps: `monitor-api`, `ndarray`/`ndarray-stats`, `clap`.

- `src/bin/trace/src/main.rs` — `Cli`/`RunCli`/`Subcommand` (`Stat`) clap types; builds a `TraceBase`-backed `ObjectBuilder` object, loads/runs the target compartment while trace events (`CONTEXT_FAULT`, `THREAD_SAMPLE`, `THREAD_CONTEXT_SWITCH`, etc.) are captured.
- `src/bin/trace/src/tracer.rs` — `Tracer`/`TracingState`/`TraceSource`/`BaseWrap`/`TraceDataIter`: manages the trace buffer/base object, iterates recorded `TraceEntryHead`/`TraceData` entries; `start()` kicks off tracing for a spawned compartment.
- `src/bin/trace/src/stat.rs` — `stat(state: TracingState)`: post-processes captured trace data (using `ndarray`/`ndarray-stats`) into aggregate statistics printed to the user.

## src/bin/unittest

Test-runner binary: discovers and runs all userspace test/benchmark binaries in the initrd, invoked by `init` when booted with `--tests`/`--bench(es)`. Package `unittest`; deps: `unittest-report`, `monitor-api`, `serde_json`.

- `src/bin/unittest/src/main.rs` — `try_bench(path)` reads a list of test-binary name-prefixes from `path`, matches them against `/initrd` entries, spawns each as a child process with `--bench`, and aggregates a `unittest_report::Report`/`ReportInfo`/`TestResult` summary shared via a `OnceLock<Report>`.

## src/bin/unittest/unittest-report

Small shared library crate defining the JSON-serializable test-report schema used between `unittest` and individual test binaries. Package `unittest-report`; deps: `serde`, `serde_json`.

- `src/bin/unittest/unittest-report/src/lib.rs` — `Report` (`status: ReportStatus`), `ReportStatus` (`Pending`/`Ready(ReportInfo)`), `ReportInfo` (`time`, `tests: Vec<TestResult>`), `TestResult` (`name`, `passed`); `Report::pending`/`ready`, `FromStr` impl parsing from JSON.

## src/bin/uuhelper

Multi-call binary bundling many uutils/coreutils utilities (`ls`, `cat`, `echo`, `sort`, `date`, etc., from a Twizzler fork of the `coreutils` project) behind one executable, dispatched by argv[0]/subcommand — `init` symlinks each utility name to this binary. Package `uuhelper`; deps: ~35 optional `uu_*` crates (git dep on `twizzler-operating-system/coreutils`, feature `feat_os_twizzler`), `uucore`, `clap`/`clap_complete`/`clap_mangen`, `phf`/`phf_codegen`.

- `src/bin/uuhelper/build.rs` — build script generating the `utils_map.rs` (`util_map()`) mapping utility name -> `uumain` entry point, via `phf_codegen`, included at compile time.
- `src/bin/uuhelper/src/main.rs` — `main()` dispatches based on the invoked binary name (`binary_path`/`name`) or first argument to the matching uutils `uumain`, falling back to prefix matching; `usage()`, `gen_completions`/`gen_manpage`/`gen_coreutils_app` implement `--list`/`completion`/`manpage`/`--help` meta-commands.

## src/bin/virtio

Standalone virtio-net + smoltcp TCP echo-server smoke test, run directly against the virtio-net device (no net-srv involved). Package `virtio`; deps: `smoltcp`, `virtio-net`.

## tools/xtask — the build orchestrator (drives everything `cargo xtask ...` does)

Host-only tool crate (`package.metadata.twizzler-build = "xtask"`); parses CLI subcommands and drives cargo's own libraries (the `cargo` crate itself, as a library) to cross-compile the Kernel/Userspace/Userspace-static/tests collections, assemble a disk image, and boot QEMU.

- `tools/xtask/src/main.rs` — CLI entry point (`clap`-based); defines the top-level `Commands` enum (build, check, doc, make-image, start-qemu, toolchain, disk, ...) and `Profile`/target selection options.
- `tools/xtask/src/build.rs` — Core build logic: invokes the `cargo` crate's compilation APIs directly (`Workspace`, `CompileOptions`, `Compilation`) to build each collection with the right target triple/flags; defines `TwizzlerCompilation`.
- `tools/xtask/src/disk.rs` — Creates/formats the ext4 disk image (via `ext4_lwext4`/lwext4-rs) and copies built Twizzler binaries into it.
- `tools/xtask/src/image.rs` — Assembles the bootable image: gathers per-crate initrd files from the compilation output and writes the final image (`ImageInfo`).
- `tools/xtask/src/qemu.rs` — Launches QEMU (`QemuCommand`), wires up serial/test-result reporting via `unittest-report`, implements `--tests`/`--benches`/`--gdb` support.
- `tools/xtask/src/triple.rs` — Defines `Arch` (X86_64, Aarch64), `Machine` (Unknown, Rpi3, Virt, Morello), `Host` (None, Twizzler, Build), and the combined `Triple` target-triple type used throughout xtask.
- `tools/xtask/src/toolchain/mod.rs` — Toolchain subcommand dispatch (`pull`/`bootstrap`/`ports`) and `BootstrapOptions`.
- `tools/xtask/src/toolchain/pathfinding.rs` — Resolves paths to the active toolchain's `rustc`/`rustdoc`/binaries based on a generated toolchain tag.
- `tools/xtask/src/toolchain/utils.rs` — Toolchain download/extract helpers (uses `reqwest`/`git2`), tarball fetch-and-unpack for `cargo toolchain pull`.
- `tools/xtask/src/toolchain/ports.rs` — `cargo toolchain ports <name>...` dispatch table (python3, llvm, zlib, ncurses, openssl, binutils, curl, psl, rust) for building/installing ported C libs into the sysroot.
- `tools/xtask/src/toolchain/ports/{binutils,curl,llvm,ncurses,openssl,psl,python3,rust,zlib}.rs` — Per-library build recipes (configure/make invocations) for `cargo toolchain ports`.
- `tools/xtask/src/toolchain/bootstrap/mod.rs` — `cargo toolchain bootstrap` orchestration: builds LLVM, rustc, and libc from source for the target triple.
- `tools/xtask/src/toolchain/bootstrap/{libc,llvm,rust}.rs` — Per-component bootstrap build steps.
- `tools/xtask/src/toolchain/bootstrap/prep.rs` — Generates `config.toml` for the rustc build.
- `tools/xtask/src/toolchain/bootstrap/mover.rs` — Copies/stages built bootstrap artifacts into the final toolchain layout.
